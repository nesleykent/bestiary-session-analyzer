# Bestiary Session Analyzer

> **Naming note:** the repository and application are still called **Bestiary Session Analyzer** for now. The product has grown well beyond that original scope; the name will be revisited separately.

Bestiary Session Analyzer is a local-first Tibia character-progress and hunt-planning workspace. It keeps long-term progress for Bestiary, Bosstiary, charms, achievements, quests, titles, and Measuring Tibia, then combines that character record with the player's own Hunt Analyzer sessions to estimate completion time, compare hunts, and plan what to do next.

The core model is deliberately simple:

1. **Track character progress** — the durable facts about what a character has unlocked or completed.
2. **Measure hunt performance** — duration and creature kills parsed from copied Hunt Analyzer text.
3. **Plan the next objective** — estimates and recommendations built from the character's progress and the player's measured kill rates.

A session measures speed; it does not replace the character's progress record. Bestiary kills entered anywhere are character-wide and immediately affect every session, comparison, opportunity, and plan that uses that creature.

## Features

### Character progress

| Feature | Purpose |
|---|---|
| **Dashboard** | Summarizes the active character's progress across every tracker. |
| **Bestiary** | Tracks creature stage or exact kills, completion, charm points, Echo Warden, Animus Mastery, and bookmarks. Its progress is the source of truth used by Bestiary session analysis and planning. |
| **Bosstiary** | Tracks boss kills and progression through Prowess, Expertise, and Mastery, including earned boss points and the next stage. |
| **Charms** | Tracks the unlock stage of Major and Minor charms, their effects, spent currency, next-stage costs, and remaining budgets. Major charms use charm points earned through Bestiary; Minor charms use echoes generated by Major charm stages. |
| **Achievements** | Tracks earned achievements and achievement-point progression, with grade, category, rarity, secret status, and bookmarks. Measuring Tibia area achievements are derived automatically. |
| **Quests** | Tracks quest completion states, questlog groups, rewards, and bookmarks. The current data model records completion rather than individual quest steps. |
| **Titles** | Tracks earned titles, unlock requirements, permanence, and bookmarks. |
| **Measuring Tibia** | Tracks Cyclopedia Map discovery across areas and subareas, shows related Bestiary creature counts, and completes the corresponding area achievements automatically. |
| **Record progress** | Searches every tracker from one command so a single value can be updated without navigating away. Press `/` to open it. |
| **Characters** | Keeps independent progress, sessions, and plans for multiple characters in the same browser. |

### Planning and sessions

| Feature | Purpose |
|---|---|
| **Charm Points Plan** | Uses selected Bestiary entries, character progress, measured kill rates, available play time, respawn mode, and spawn availability to maximize fully earned charm points and recommend a route. |
| **Opportunities** | Finds unfinished Bestiary opportunities: efficient measured hunts, entries closest to completion, locations with unclaimed charm points, and started creatures with no stored session. |
| **Bestiary Session** | Parses one Hunt Analyzer, matches its creatures to the Bestiary, and estimates kill rate, kills remaining, completion time, and charm-point efficiency. |
| **Bestiary Sessions** | Shows analyzed entries from all sessions together while preserving each session's own measured rate. |
| **Compare Sessions** | Ranks measured sessions by remaining charm points, longest completion time, and projected charm rate. |
| **Session History** | Stores and manages every session with its name, hunt date, notes, duration, recorded respawn mode, creatures, and calculated results. It supports search, sorting, reopening, and deletion. |
| **Task Sessions / Task Estimate** | Uses a session's measured creature kill rate to estimate a user-defined kill target, such as a Bounty or Weekly task. Task targets remain separate from Bestiary thresholds and charm calculations. |

## How the calculations work

### Hunt evidence and character truth

- **Session kills** come from one pasted Hunt Analyzer. They determine the measured kill rate for that hunt.
- **Total kills** are the active character's persistent Bestiary progress. A creature has one total shared by every session in which it appears.
- The app does **not** automatically add session kills to total kills. A copied log does not reveal whether the in-game Bestiary total already includes those kills.
- When only a Bestiary tile (`?`, `0/3`, `1/3`, `2/3`, or `✓`) is known, the app uses the minimum kill count implied by that stage and qualifies the estimate accordingly.

### Bestiary estimates

For a matched creature:

```text
kill rate       = session kills / session duration
kills remaining = Bestiary unlock target - character total kills
time remaining  = kills remaining / measured kill rate
charm rate      = remaining charm-point reward / time remaining
```

Within one hunt, selected creatures progress at the same time, so a session's completion time is the longest remaining creature time—not the sum of every creature time.

### Charm Points Plan

The planner treats charm points as discrete rewards: partial Bestiary progress earns no charm points until the entry is complete. It:

- uses only selected creatures from eligible sessions;
- separates `Regular` and `Rapid Respawn` measurements instead of converting between them;
- lets a temporarily unavailable spawn be ignored without deleting its session;
- advances all selected creatures in the same session simultaneously;
- searches across session-time allocations for the most fully earned charm points within the entered time;
- prefers less time when two plans earn the same number of points.

### Opportunities

Opportunities crosses the complete Bestiary dataset with character progress and stored session rates. It can therefore surface more than creatures already present in a session:

- **Finishable Now** — unfinished creatures with a measured rate, ranked by projected charm rate.
- **Quick Wins** — started entries closest to completion, with or without a stored rate.
- **Where To Go** — locations ranked by unclaimed charm points.
- **Started And Dropped** — progress that no stored session currently measures.

### Task estimates

Tasks reuse Hunt Analyzer performance without using Bestiary rules. Choose a creature observed in the session and enter a kill-count target; the app reports the measured hourly rate, session kills, remaining kills, and estimated time. Recorded respawn mode is shown as context but does not alter the rate.

## Main workflows

### Record character progress

1. Select or add a character.
2. Open a tracker from the sidebar, or press `/` to record one value quickly.
3. Use the tracker controls to record stages, counts, or completion states.
4. Filter, sort, bookmark, or open an entry for more detail.
5. Use the tracker-specific CSV import/export controls when entering progress in bulk.

The manual tracker-entry contract—including unknown values, confirmed zero/no, sequential review, and resume behavior—is documented in [Tracker Data Entry UX](docs/tracker-data-entry-ux.md).

### Analyze a Bestiary hunt

1. Open **Charm Points Plan**, **Opportunities**, or **Session History**, then create or open a session.
2. Paste the Hunt Analyzer text.
3. Record whether the hunt used `Regular` or `Rapid Respawn` conditions.
4. Select **Process log**.
5. Choose which matched creatures belong in the estimate.
6. Review kill rate, shared Bestiary progress, kills remaining, completion time, and charm rate.

### Compare and plan hunts

1. Process at least two sessions.
2. Use **Compare sessions** to rank whole-session results.
3. Use **Bestiary Sessions** to choose which session should represent an objective when a creature appears in several hunts.
4. Open **Charm Points Plan**, enter the available play time, choose the respawn mode, and mark unavailable spawns.
5. Follow the recommended route or open a supporting session to adjust its inputs.

### Estimate a task

1. Open **Task Sessions** and select or create a session.
2. Process a Hunt Analyzer.
3. Select the task creature from those observed in the log.
4. Enter the desired kill-count target.
5. Review the remaining kills and time estimate based on that session's measured rate.

## Data, persistence, and privacy

- The app is static and requires no account or backend.
- Character progress, sessions, notes, and plans persist in browser `localStorage` across tabs and browser restarts.
- Data is local to that browser profile unless a workspace backup is exported and imported elsewhere.
- **Export** downloads one JSON backup containing every character and each character's trackers, sessions, and planning state.
- **Import** restores a workspace backup and replaces all currently stored characters after confirmation.
- Individual trackers support CSV export and CSV import; Bestiary and Bosstiary also accept supported TibiaDraptor JSON progress.
- **Recent changes** keeps a reversible trail for recorded tracker changes.
- **Clear all data** permanently removes this application's saved browser data after an explicit confirmation.
- No credentials are requested, and the app does not connect to a Tibia account.

## Running locally

This is a dependency-free static application. Start a server from the repository root:

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Then open:

```text
http://127.0.0.1:4173/src/
```

After editing a JavaScript module or stylesheet, use a hard reload (`Cmd+Shift+R` or `Ctrl+Shift+R`) if the browser keeps an older module. See [CONTRIBUTING.md](CONTRIBUTING.md) for the project workflow and cache-safe local server option.

### Example Hunt Analyzer text

```text
Session: 01:30h
Killed Monsters:
    250x Rotworm
    500x Cyclops
Looted Items:
```

The parser currently reads `Session: HH:MMh` and the creature lines between `Killed Monsters:` and `Looted Items:`.

## Architecture

```text
src/
├── app/
│   ├── features/   # parsing, Bestiary analysis, opportunities, comparisons, plans, tasks
│   ├── services/   # read-only dataset loaders
│   ├── state/      # characters, sessions, progress, persistence, import/export, undo
│   ├── trackers/   # one definition per progress tracker
│   ├── ui/         # shared renderers and view-specific presentation
│   └── main.js     # application orchestration and browser events
├── data/           # bundled Tibia metadata snapshots
├── styles/         # design tokens and application styles
└── index.html      # application entry point
```

Important design boundaries:

- Tracker definitions derive totals and status from read-only game data plus minimal user-owned progress.
- Sessions own raw Hunt Analyzer evidence and contextual metadata, not character-wide Bestiary totals.
- Planning and comparison views consume the same calculated session summaries shown in session detail.
- Measuring Tibia derives matching achievement completion instead of storing the same fact twice.

More detail is available in [Repository Structure](docs/repository-structure.md) and [Product Journey](docs/product-journey.md).

## Limitations

- Estimates are projections from the pasted session, not guarantees of future in-game performance.
- Respawn conditions, route changes, party composition, boosts, competition, and player execution can change actual results.
- Hunt Analyzer parsing expects the text structure shown above.
- Quest tracking currently records per-quest completion, not arbitrary intermediate quest steps.
- This is an unofficial fan tool and is not affiliated with CipSoft.
